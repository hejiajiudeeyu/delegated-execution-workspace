## 一、交互铁律(所有面板强制,逐条对应摩擦)

| 铁律 | 消灭的摩擦 |
|------|-----------|
| R1 每个操作在**按钮旁边**给出即时反馈:成功=绿色内联条,失败=红色内联条+人话解释+建议动作;raw JSON 一律降级为折叠的"技术详情" | M3 |
| R2 **非 2xx 响应绝不渲染成空态**。401/403 → "凭据问题"引导卡(带直达配置的按钮);5xx → "网关/平台异常"卡+重试;只有真正的空结果才显示空态 | M6、M5 |
| R3 凭据保存必须**先验活再入库**:保存时网关实调一次 platform-api,失败则拒存并内联报错;徽章语义 = "已验证",不是"已填写" | M10 |
| R4 破坏性/资金类操作:无默认值、必填校验、二次确认(确认框回显将发生的事);确认词输入框 placeholder 用提示语("在此输入 RESET"),**绝不**用与答案相同的字面 | M2、M9 |
| R5 每个数据区块四态可分辨:未查询(引导)/加载中(骨架)/为空(明确"查询成功但无数据")/出错(R2) | M8、M6 |
| R6 输入即查:关键查询(如 tenant_id)失焦或回车自动加载,不依赖"先填再找按钮" | M8 |
| R7 状态用语全局统一(中文优先):未初始化 / 已锁定 / 已解锁 / 网关不可达;徽章、面板、文档三处一词 | M4 |
| R8 构建产物文件名带内容指纹,index.html no-cache——发版后浏览器绝不拿旧 JS | M1 |
| R9 需要前置条件的面板(admin key 未验证时的审批/计费/审计),渲染**前置引导卡**而不是让用户撞 401 | M5 |
| R10 全局操作路径提示:每个面板顶部一句"这里能做什么+下一步去哪",向导场景给步骤条 | owner"指引不清" |

## 二、信息架构(沿用分组,重排会话流)

```
侧边栏:总览 / 运营(审批队列、请求)/ 目录(Responders、Hotlines、Marketplace)
        / 计费 / 审计 / 设置(会话与解锁、网关凭据)
顶部常驻:会话状态徽章(R7 四态)+ 当前操作者提示
```

关键流程重设计:
1. **首次/恢复向导**(mockup 01):检测到"已锁定且你没有口令"或"未初始化"时,进入 3 步向导:①粘贴 bootstrap secret(注明来源=部署方 `.env`,给 ssh 一行命令可复制)→ ②设置新口令(强度提示+二次输入)→ ③输入确认词 RESET(实时校验,不合法按钮禁用)。每步只做一件事。
2. **解锁后强制引导**:若 admin key 未验证,全局琥珀色横幅"管理凭据未配置——审批/计费/审计不可用 → [去配置]",点击直达;凭据页保存即验活(R3)。
3. **计费**(mockup 03):tenant_id 回车即查(R6);存在→余额卡+人话账本(kind 徽章:充值/冻结/结算/退款);不存在→内联提示"未找到,是否创建?"此时才亮 Create。充值金额默认空、二次确认回显"将为 user_xxx 充值 20000 PTS"。
4. **审批队列**(mockup 02):Tab=待审 / 最近处理;卡片显示生命周期进度条(submit→pending→approved→enabled);批准/启用逐动作内联反馈;空态写"当前无待审;上一条处理:xxx(时间)"。

## 三、视觉方向

- 与 client ops-console 同族:白卡片、12px 圆角、细边框(#e5e5ef)、主色紫(#7c5cff)、成功绿/危险红/警示琥珀;中文为主、等宽字体只用于 id/代码
- 密度中等,行高宽松;id 类信息一律可一键复制
- raw JSON:统一折叠组件"技术详情",默认收起,深色代码块

## 四、工程要点(实现阶段约束)

- 统一 API client 层:所有网关调用收敛一个模块(错误分类、会话 token 注入、超时);未来 API 演进只改此层
- 组件库:沿用 ops-console 的组件范式(卡片/徽章/toast/空错载入态组件化),测试用同一套 vitest+testing-library 方案
- 退役 `apps/platform-console/src/*.tsx` 旧 React 原型(quarantine → 删除)
- 自动化浏览器回归:现有 Playwright 全流程脚本改造为新 UI 的验收脚本,进入 platform 仓 e2e 家族

## 五、验收标准(2.0b 完成定义)

1. Playwright 全流程绿:恢复向导→解锁→凭据验活→审批→计费→账本,全程无 raw-JSON-as-UI
2. M1–M10 逐条复核关闭(映射表打勾)
3. owner 人工走查:不看文档能独立完成一次审批+充值,主观评价"可用且不别扭"
4. 发版走 tag→Images→滚生产;老 UI 不保留切换开关(一次性替换)
