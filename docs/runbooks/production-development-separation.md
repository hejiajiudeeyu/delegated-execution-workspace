# 生产与开发的分离（运营层）

Created: 2026-08-07 · 起因：owner 提问「是否要隔离生产环境和开发环境」，查证后发现已经在付代价

## 为什么有这份文件

2026-08-07 查生产时的实际状态：

- 公开目录 4 条热线，**3 条是六七月彩排残留**，全部 `enabled` 且离线一到两个月
- 待办聚合常年 **12 项，其中 11 项是残留**（7 条卡住的测试调用 + 4 台已消失的彩排设备）
- 这台开发机有 **10 个 `~/.delexec*` 目录**，默认那个指向 `127.0.0.1:8080`，名下挂着 `cli.invalid.guidance.v1`、`cli.toggle.v1` 之类的东西

最要命的一条：FR-066 告警复用的正是 `buildAttentionItems()`。**填上 webhook URL 的那一刻，第一批告警就会是六月的测试调用**，而且当时没有任何 operator 动作能让它们闭合——每 6 小时永远重播。CHG-2026-197 写下的承诺是「告警之后的沉默一定意味着已解决」，一个谁也解决不了的条目会把这个承诺对**所有**条目一并作废。

这不是洁癖问题。一个从不为空的待办列表，训练人忽略它。

## 已经做了什么（2026-08-07，CHG-2026-203）

- 平台补上两个 operator 动作（v0.4.9）：`POST /v1/admin/requests/:id/close`（必须写理由；有冻结资金则退款；**永不结算**）与 `POST /v2/admin/responders/:id/retire`（撤回设备"我在服务"的声明，记录保留）
- 生产清理：3 条残留热线停用、7 条卡住调用逐条收口并写审计、4 台彩排设备退役
- 结果：**待办 12 → 1**，剩下的 1 项是真的（MinerU 设备确实离线）

## 规则

### 1. 开发一律打本地栈

不要把开发中的客户端指向 `callanything.xyz`。本地栈起法见 `repos/platform/deploy/public-stack`，或 `corepack pnpm run dev:local:up`。

### 2. 生产设备用专属、非默认的 `DELEXEC_HOME`

默认路径（`~/.delexec`）留给开发。生产设备显式指定，例如：

```bash
DELEXEC_HOME=~/.delexec-prod delexec-ops <command>
```

理由：默认路径那份配置里现在就躺着测试热线。**误投生产只差一个未设置的环境变量。**

### 3. 彩排产生的东西，彩排结束就退役

热线停用 + 设备退役 + 调用收口，三件一起做。只停用热线是不够的——待办聚合读的是 `responder.hotline_ids`，停用热线不改变设备名下挂着什么。

### 4. 开告警之前，先把待办清到「每一项都是真的」

顺序不能反。告警上线第一天喊狼来了，之后你就不会再信它。

## 尚未做（结构层）

本轮只做**运营隔离**（owner 2026-08-07 选择）。结构层的隔离——把信任域做成真正的「网络」对象，让开发网络与生产网络天然不相通——是 FR-001 至今 `partial` 的原因，仍未做。在那之前，分离靠的是上面这几条纪律，而纪律会被疲劳打败。
