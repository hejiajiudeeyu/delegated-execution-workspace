# v0.2.0 Console 诊断：为什么第二次重建也没成

Created: 2026-08-01 · 输入 = owner 二次判定"逻辑、操作动线根本看不懂"
方法：读 `repos/platform/apps/platform-console/src` 全部源码（4925 行），不是凭观感

## 先承认一件事

这是**第三次**要重做 console：

| 次 | 时间 | 做法 | 结果 |
|---|---|---|---|
| 1 | v0.1.x | 迭代改进 vanilla console | owner 走查出 M1–M10 十条摩擦 |
| 2 | v0.2.0（2026-07-04） | 设计稿 → 拍板 → React SPA 推倒重建 | **就是现在这个"完全不能用"的版本** |
| 3 | 现在 | ? | ← 如果不换方法，大概率得到第三个不满意的东西 |

第二次修的是**交互细节**（内联反馈、非 2xx 不渲染空态、凭据验活、危险操作无默认值、资产指纹）——这些都修对了，且现在仍然成立。但它们是**同一个信息架构上的表面修复**。owner 这次的判定（根子在"不知道下一步干啥"+"看不懂屏幕上的东西"）说明问题在架构层，不在交互层。

## 根因：它是一个 CRUD 浏览器，不是一个工作台

### 证据 1：导航按 API 端点分页，不按任务分

`src/App.tsx` 的十条路由：`overview / session / credentials / reviews / requests / responders / hotlines / marketplace / billing / audit`。

这是 **platform-api 的资源清单**，不是 operator 脑子里的任务清单。owner 自述的三大用途是"推进一件具体的事 / 查一件事的来龙去脉 / 首次部署配置"——这三件事**没有一件**能映射到某个单页上。

### 证据 2：「下一步」只覆盖开局三步，之后永久沉默

`src/pages/OverviewPage.tsx:33-39` 的 `nextStep` 只有三个分支：

```
未解锁      → 去会话页
凭据未验证  → 去凭据页
否则        → "一切就绪。新提交会出现在审批队列。"
```

**一旦完成初始化，首页就再也不知道该干什么了。** 它不接任何业务信号——不知道有几条待审、有没有卡住的调用、有没有冻结的资金、有没有设备离线。首页的健康卡只报三件事：网关活着、会话解锁、凭据有效。

这不是设计师忘了写，是**这个页面没有接入任何业务数据源**。"不知道下一步干啥"有精确的机制解释。

### 证据 3：五个语义不同的页面共用一个渲染器

`src/pages/ListPages.tsx` 用一个 `GenericListPage` + `ListSpec` 渲染 Requests / Responders / Hotlines / Marketplace / Audit。每条记录 = 一张卡 + `<TechDetails raw={JSON.stringify(item, null, 2)}>`。

一个调用、一台设备、一条热线、一条审计事件，在视觉和结构上**长得一模一样**：卡片 + 原始 JSON dump。

### 证据 4：「查一件事的来龙去脉」在信息架构里不存在

全站**没有任何 detail 路由**。有 `/requests` 列表，没有 `/requests/:id`。

所以追查一次调用，你必须：在 Requests 页找到那张卡 → 展开 JSON → 把 caller_id 抄下来 → 去 Billing 页手输它查余额 → 去 Audit 页翻找相关事件 → 自己在脑子里拼时间线。**三个页面之间没有一条链接。**

### 证据 5：屏幕要你填你不知道从哪来的东西

`src/pages/BillingPage.tsx:98-104`：「租户 ID（输入后回车或失焦自动查询）」——一个空输入框。

而 `tenant_id` 实际等于 caller 的 `user_id`，你得先从别处抄过来。这是"语义看不懂"的标本：**界面把内部主键当成用户已知的输入**。

### 证据 6：四个状态字段并排显示，关系要你自己想

`ListPages.tsx:69+` 的 `StatusBadges` 同时渲染 `review_status`、`status`、`catalog_visibility`、`availability_status`。一条热线可能同时是「已批准 / 已启用 / 公开 / 离线」——四个词，四套语义，没有任何一处解释它们的关系（其实是：审核通过 **且** 启用 → 才公开；离线是心跳推出来的，与前三者正交）。

### 证据 7（新增）：信息模型已经落后于系统

今天（2026-08-01）系统新增的东西，console **一个都不知道**：设备容量与版本、maintenance 状态、artifact 通道、四轴状态模型（执行/交付/验收/资金）。

**即使 UI 重画得完美，它展示的仍是一个过时的世界。**

## 提案：从「对象浏览器」变成「任务工作台」

不是换皮肤，是换组织原则。三条主线对应 owner 的三大用途：

### 主线 A —— 首页 = 真实待办，不是健康灯

首页回答"现在有什么事需要我"，每一条都是可点击的行动项：

- 待审热线 3 条 → 进审核流程
- 卡住的调用 1 个（executing 超过 timeout+grace）→ 进调用详情
- 冻结资金 1 笔（争议中）→ 进争议处理
- 设备离线 1 台 / maintenance 1 台 → 进设备详情
- 版本漂移（运行时 ≠ 认证组合）→ 进版本页

**没有待办时明确说"没有需要你处理的事"**，而不是显示三盏绿灯让人猜。

### 主线 B —— Call 详情页 = 系统的脊柱

一个 `/calls/:id` 页面，把今天散在四处的东西聚合成**一条时间线**：

```
提交 → 接受 → 执行 → 交付 → 校验 → 验收 → 结算
  ├ 执行状态轴（四轴之一，各轴独立显示，不再压成一个 status）
  ├ artifact 清单（名称/大小/checksum/是否已提交）
  ├ 资金分录（hold → settle/refund，金额与时间）
  ├ 相关审计事件
  └ 涉及的设备与热线版本（可跳转）
```

这一个页面同时解决"查来龙去脉"和"四个状态字段看不懂"——因为四轴**本来就是四条独立的线**，画成四条就不需要解释了。

### 主线 C —— 任务向导，不是散落的按钮

有开始有结束的流程，每步说清楚"为什么要这一步"：

- **首次配置**：解锁 → 凭据 → 接入第一台设备 → 验证一次调用（一条路走完，不是三个页面自己找）
- **审核一条热线**：看契约 → 看示例 → 跑审核测试 → 批准/驳回（驳回必须填理由，理由会呈现给提交者）
- **给调用方开户**：选身份（**从已注册用户里选，不是手输 ID**）→ 建租户 → 充值 → 确认

### 横切 —— 术语层

每个内部字段名旁边一句人话；`tenant_id` 这类必须能从上下文带出来，绝不让人手抄。

## 建议的下一步（按顺序）

1. **owner 确认这个诊断和三条主线的方向**（如果方向不对，界面画得再好也白搭——前两次就是这么失败的）
2. 补齐 console 需要但平台还没有的读接口：待办聚合、Call 聚合视图（当前 API 只能分别查 requests / billing / audit，前端 join 会很脏）
3. 再谈界面

**明确不做**：不动 brand site（owner 决定，官网现在没有真实访客，console 是每天要用的）。

## 一个不舒服但必要的提醒

第 2 步（补后端聚合接口）会诱人跳过——"先用现有 API 拼一下看看"。前两次失败可能正源于此：**信息架构受限于 API 形状，于是只能按端点分页**。如果这次还是在现有 API 上画界面，很可能得到第四个 CRUD 浏览器。

## 执行结果（2026-08-02 追记）

三条主线全部落地（CHG-2026-193，platform `373ca64`，随 v0.4.2 上生产）：

- **主线 A 首页 = 真实待办** ✅ 每行可点进处理；无事时明说；并显式列出"这个页面还看不到什么"。
- **主线 B `/calls/:id`** ✅ 时间线 + artifact（已提交/已分配可辨）+ 资金 + 设备热线聚成一页；四轴画成四条独立的行；未跟踪的轴标注原因；租户 id 由链接带过去。
- **主线 C 任务向导** 部分：审批动线**本来就存在**（`ReviewQueuePage`），本轮实证可用后未重建；首次配置与开户向导未做。

**诊断里一处判断需要修正**：证据 2 说首页"不接任何业务数据源"是对的，但当时推论"审批也无处可点"并不成立——审批 UI 一直在。

**还挖出一个更难堪的原因**：console 的**开发服务器从来连不上 gateway**。DEV 模式下 API base 传了裸 `/`，`new URL()` 拒绝相对 base，抛出的异常被归类成 gateway_down——所以本地开发看到的永远是一个连不上后端的死界面。**前两次重做都是在这个状态下开发的。** 这大概比信息架构更能解释"为什么两次都做成了 CRUD 浏览器"：没人能在开发时看见真实数据长什么样。已修，并加了单测钉住。
