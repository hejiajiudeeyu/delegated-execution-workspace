### 单元 2 — 验收门：结算等验收（FR-041/FR-044，platform 为主）

- **拆 applyTerminalBillingIfNeeded**（1110-1194）：FAILED→退款一半原样保留（reconcile @4854 强制 FAILED、hold 过期 @885、admin close @5957 三个退款调用方都不动）；COMPLETED 分支改为**开验收窗**，结算移入新 `settleAfterAcceptance`——仅显式 accept 与 auto-accept 两个调用方，`billing.state==='held'` 幂等闸原样继承（零重复资金事件的结构保证）。
- 验收记录：`request.acceptance = {status, window_opened_at, deadline_at, decided_at, decided_by}`；**时钟起点 = 单元 1 的 delivery verified 钩子**，不是 COMPLETED（A-05 明文；投影 EXECUTION_FROM_LEGACY_EVENT 的 COMPLETED→delivered 是错误触发器）；deadline = opened_at + `request.service_terms.acceptance_window_s`（快照 @3071 就是为这一天存的，读法照 1438/5848——绝不回目录补）。integrity=failed 的交付**不开窗**（验收轴等修订/争议处理，归单元 3 语义）。
- **auto-accept 机制（照抄本平台的既有时间模式，勘察点名）**：懒评估 `autoAcceptIfWindowExpired` 挂在 expireHeldBillingIfNeeded 的同一批读触点（GET events 4923 / batch 4980 / balance 5342 / ledger 5373）+ **alert loop 分钟拍作扫尾**（alerts.js:391 唯一真 interval），过期即以 actor_type:'platform' 追加 AUTO_ACCEPTED 事件后结算——与 919 行合成 FAILED 同一形状。不做 per-call timer。
- caller 路由：`POST /v1/requests/:id/accept`，requireCaller + `request.caller_id === auth.user_id` 所有权检查（照 delivery-meta 4460-4540 的既定模式，落在同一路由块），非 pending 409，重放幂等返回既有决定。accept 与 sweep 的竞态由 settleAfterAcceptance 的 held 闸收敛——**exactly-once 断言必须覆盖这条竞态**。

- 附带必改：`funds_held_after_end` 注意项（3881-3895）排除验收窗未到期的 held——否则每个健康待验收调用**每 6 小时告警一次**；补 `acceptance_expiring` 项（kind 名在 5675-5678 已预占）。顺手修 admin 详情 settled_amount_cents 读错字段（5869 读的 key 与 1178 写的 `actual_amount_cents` 不一致，永远显示 null）。
- **裁定点（报 owner）**：webhook 的 result_url 指向不存在的 `GET /v1/requests/:id`（勘察实证全路由表无此路由）；验收门若无任何平台侧可读的交付面，"接受"可能沦为盖章。选项：a) 补 caller 鉴权的请求详情只读路由；b) 依赖 relay 侧已送达的结果包，result_url 改指真实入口。

### 单元 4 — Caller 主动取消（FR-024，platform + client）

- 克隆 admin close 骨架（5914-6003：理由必填 / 终态拒绝 / CANCELED 事件 / held 才退款 / 结构上永不结算）为 `POST /v1/requests/:id/cancel`，caller 鉴权 + 所有权，已交付明确拒绝（协议 DELIVERED 转移表为空，本来就无路可转）。
- **顺带修既有缺陷（勘察实证）**：CANCELED 之后到达的 COMPLETED 仍会追加并把 projectExecutionState（last-event-wins，3798-3807）翻回 delivered——钱是安全的（held 闸），**状态在撒谎**。以 validateCallStateTransition 挡终态后终态；这同时修掉"TASK_TOKEN_EXPIRED 退款后迟到 COMPLETED 翻轴"的同形状问题（单元 6 的勘察发现，同一处代码，一次修完）。
- 取消时吊销 task token（未派发的任务在 responder introspect 处死掉，1271 已是拒绝路径）；执行中的取消**尽力而为**，如实文档。
- client：ops CLI + caller-skill-adapter 补 cancel 动作（agent 面只经 skill-adapter，M3 harness 的合同）。

### 单元 5 — 执行前 ACCEPTED / REJECTED（FR-021，platform + client；携带本轮唯一产品级裁定）

- **裁定点（开工前 owner 多选题，勘察定性为"伪装成管道的产品决策"）**：协议冻结的不变量是 rejected ⇒ settlement **none**（call-state.js:301-305，"拒绝的调用不得持有**或移动**资金"）——refund 也不合法，所以"发 token 即 hold、拒绝再退"在协议上就是非法状态。选项：
  a)（推荐，协议唯一自洽解）hold 移到 responder accept 时刻：token 签发保留同意+余额校验（1009 的 402 不动），ledger hold 延后到 ACCEPTED 落账；REJECTED 什么都不写。代价：余额不足的**暴露时点**从发起挪到接受，且 accept 前有一段无 hold 的窗口。
  b) 维持现状，FR-021 只做状态不动钱（rejected 调用仍走 hold→refund，协议不变量降格为文档）——不推荐，等于把刚冻结的协议规则当装饰。
- 路由：responder 侧 `POST /v1/requests/:id/accept|reject`（或扩展 ack 体）；EXECUTION_FROM_LEGACY_EVENT 补 ACCEPTED/REJECTED 映射（现在投影根本说不出这两个词）。
- **顺带收编既有的事实拒绝路径**：guardrail 失败与 token 过期拒绝（responder-runtime-core 692-737 / 1271-1288）现在都被包装成 COMPLETED-with-error，正是 FR-021 禁止的"拒绝了却拿着钱"形状——迁到显式 REJECTED。

### 单元 6 — 排队与超时预算（FR-025，protocol 已备 + platform + client + deploy env）

- **queued 作为真生命周期事件**：协议 QUEUED/EXECUTION_STARTED 事件名与转移表 M1 就冻结了（**但全协议测试树零覆盖，先补红先测试**）；平台 events 路由收编这两个事件、投影补 QUEUED→queued / EXECUTION_STARTED→executing、ACKED 降格为 queued（设备侧真相：ack 时任务在本地 QUEUED 里排在 workerConcurrency=1 后面）——**历史事件的投影规则要单独定**，别让旧调用的轴换意思。responder 从 runQueuedTask 发真事件，**不得**复用 PROGRESS 观测拍（协议明文禁止观测事件进执行投影，call-state.js:693-696）。
- **三个 300s 时钟拆开（杀掉 4 分钟真调用的不是一个 bug 是三个）**：① caller `hard_timeout_s || 300`（caller-controller-core:464，覆盖从创建到终态全程）；② TOKEN_TTL_SECONDS=300 兼任 token 有效期与 billing hold 过期（864/1034，deploy 两个 .env 还钉死 300）——过期即 TASK_TOKEN_EXPIRED 假 FAILED + 退款，**哪怕任务正在跑**；③ responder 热线默认 hard 180s。只改一个 = 换个错误码死。修法：预算字段进冻结契约（见下），三处都从预算派生；token 在 QUEUED/EXECUTION_STARTED 时续期或 hold 改用预算时钟。
- **预算入契约（contracts 发版，可并入 0.1.11 或单独 0.1.12——按设计成熟度定，报 owner）**：`HOTLINE_VERSION_CONTRACT_FIELDS` 加 digest-safe 附加字段（如 `execution_budget_s`，或按档位映射默认值并按真实 ML 量级取数——MinerU 含模型加载 ~240s+）。**红线照 service_tier 先例**（call-state.js:401-407）：默认值只在读取时解析、绝不写进既有版本记录——写了就是全网 digest_mismatch。
- 派发信封补 constraints（buildDispatchEnvelope 1047-1077 现在**不带任何时限**，responder 侧 task.constraints 恒 null，RESPONDER_MAX_HARD_TIMEOUT_S 护栏形同虚设，MinerU worker 的干净超时余量路径从未生效过）；预算权威顺序（冻结 terms > caller 收紧 > responder 上限拒绝）在协议注释写死。

## 4. 交付规则与已知陷阱（执行会话必读）

1. **四仓规则不变**：owning repo 先行 → SHA → bundle → 五件套；台账证据推动。M2 学费：**五件套本地绿不算数，CI 页面要真打开看**（CHG-2026-214 的教训写在台账里）。
2. **contracts 发版后的 lockfile 陷阱**（M2 栽过两次）：两仓 bump 下限 + `npm update @delexec/contracts --package-lock-only`，不是裸 `npm install`（会覆掉本地符号链接）。
3. **单元 1 的发布顺序不可倒**：contracts npm → platform 滚生产 → ops npm → 设备升级。校验方永远先于签名方懂新字段。
4. **授权点**（D2：花钱/删数据/对外发布回询，多选题）：contracts 0.1.10 / 0.1.11（/0.1.12）发 npm；ops 新版发 npm；生产滚 v0.4.13+。**设计裁定点**（非 D2 类但影响行为，开工时多选题）：单元 5 冻结时机（推荐 a）；单元 2 caller 交付可读面；单元 3 的 responder 范围增量确认；单元 6 预算字段并入哪次发版。
5. **时间控制先例**：平台无假时钟（nowIso 硬连 Date）。集成测试注入 now 参数（buildAttentionItems 先例）；e2e 用 use-time env（TOKEN_TTL_SECONDS 先例）。`ACCEPTANCE_WINDOW_OVERRIDE_S` 只许影响到期比较——渗进发布校验或快照就是生产事故。
6. digest-safe 加字段红线：默认值读取时解析，绝不落盘进既有版本记录（service_tier 先例，call-state.js:401-407 注释即模板）。
7. 环境陷阱（better-sqlite3 ABI、platform-api 自加载 env 等）见 memory `delegated-execution-env-quirks`。billing 平台集成测试用 pg-mem 不需要 Docker；只有两个四仓 harness 需要。
8. 史官/工作台引文不进受版本控制文件、commit、PR（本计划已核查不含）。
