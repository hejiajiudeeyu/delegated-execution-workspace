## 4. 交付规则与已知陷阱（执行会话必读）

1. **四仓规则不变**：业务改动落 owning repo → 各仓 commit 并 push（`check:submodules` 要求 SHA 可达）→ 四仓 submodule 更新 + change bundle → 五件套 `corepack pnpm run check:submodules / check:boundaries / check:bundles / test:contracts / test:integration`；合并门用 `test:release-gate`。台账状态只能由证据推动。
2. **contracts 发版后的 lockfile 陷阱**（2026-08-05 栽过两次）：本地 `repos/{client,platform}/node_modules/@delexec/contracts` 是指向协议仓源码的手工符号链接，本地永远看不见 lockfile 漂移；发版后两个仓都要 bump 依赖下限 + `npm update @delexec/contracts --package-lock-only`（不是裸 `npm install`，会覆掉符号链接）。症状：CI/镜像烟测 ESM `does not provide an export named ...`。
3. **授权点**（D2：花钱/删数据/对外发布须回询，多选题形式）：contracts 0.1.9 发 npm；ops 新版发 npm（单元 8/9/10 改了已发布字节就需要）；生产滚版 v0.4.10+。其余按推荐默认推进不回询。
4. 环境陷阱（better-sqlite3 ABI 重建、platform-api 直跑自加载 env、release-gate 读本地态等）见 memory `delegated-execution-env-quirks`。
5. 史官/工作台引文不得进入受版本控制文件、commit、PR（本计划已核查不含）。

## 5. 退出

goal.md 退出条件不变：三条真实 workflow 用同一契约表达并通过校验。本轮附加的可检验口径：**一个不与 responder 同机的 AI agent，能通过 MCP 工具链完成"发现 → 读全契约 → 正确填写 → 显式同意付费 → （confirm 热线）人工确认 → 收到完成 webhook"的完整一次调用**，全程无 SSH、无 admin curl、无人传话。
